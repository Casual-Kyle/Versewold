# Manuscript layout and PDF export

Open **Manuscript** in the main navigation, **Title page & PDF setup** in the library, or the PDF action in **Files & export**. Windows desktop saves PDFs; browser mode offers a temporary preview.

## Arrange the project

Reading order is dedication, unsectioned writing, ordered parts and their documents, then About the Author. The title page is generated from the project title and export settings; it has no duplicate Markdown file.

- **New part** creates a section. Its settings button provides rename, move up/down, and remove-part controls. Removing a part keeps its writing in the unsectioned group.
- **Front & back matter** creates or opens Dedication and About the Author. These are ordinary Markdown documents, with form guidance hidden.
- A poem's **Details** assigns its part, moves it up/down within its group, sets a byline, and edits its composition date. Part/document ordering also applies to combined Markdown exports.

Parts form a flat hierarchy. Stable IDs link documents in JSON; changing titles/order never renames or rewrites their Markdown files.

## Page setup

| Control       | Behavior                                                                                                                                                                                                 |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Paper         | Letter, A4, A5, or custom dimensions; portrait/landscape.                                                                                                                                                |
| Margins       | Four independent values in inches/mm; at least 40 mm of usable width and height remains.                                                                                                                 |
| Print font    | Search installed/bundled families; independent of interface/editor typography.                                                                                                                           |
| Type          | Body 8–32 pt, titles 10–40 pt, single through triple line spacing.                                                                                                                                       |
| Title page    | Optional author, total word count, and today's date or latest recorded revision.                                                                                                                         |
| Word count    | Every document body, including front/back matter; optionally project, part, and document titles. Uses the writing desk's whitespace-separated count. Generated bylines, dates, and numbers are excluded. |
| Bylines/dates | Optional author under each title; no date, composition date, or automatic revision date.                                                                                                                 |
| Page flow     | Separate part pages, new page per document, and numbers excluding the title page.                                                                                                                        |
| Preview       | Scroll physical sheets, jump to a page, zoom 50–125%, show nonprinting margin guides.                                                                                                                    |

Valid layout changes autosave in the project's `project.json`. Invalid partial inputs show an explanation and disable export without replacing saved settings. **Reset page setup** restores bundled defaults. Settings/source remain in `%APPDATA%\com.client.versewold\`; exported PDFs go to the native Save dialog's destination.

## Author and dates

**Preferences → Author profile** stores a default name/pen name in roaming `user-settings.json`. New projects and poems capture the default. A project author overrides the profile fallback; a document author overrides the project fallback. Existing explicit bylines stay unchanged when the profile changes. Blank legacy bylines use the fallback at export.

New documents record local `composedOn` and ISO/RFC3339 `updatedAt`. Editing text, title, author, or composition date advances `updatedAt`; unchanged saves, selections, forms/display, part assignment, and layout do not. Composition stays fixed and editable. **Last revised · automatic** prints the updating date. Clearing composition leaves it absent until a subsequent text edit. Older documents remain undated until edited or explicitly dated; historic dates are never guessed on load. Date-only values travel without timezone shifts; revision timestamps display in local time.

## Fidelity and limits

The same paginated DOM supplies preview and Windows WebView2 PDF output. Fonts finish loading before measurement/export. Canvas measures widths; positions use physical points. Print CSS removes the shell, zoom, guides, form annotations, and browser headers/footers. Long lines wrap and continue onto subsequent pages without changing source breaks. Indentation/stanza blanks remain; tabs display as four spaces. Empty trailing writing positions do not create extra blank PDF pages. Empty documents receive their titled page.

Markdown prints as source: emphasis markers, links, and body headings are literal. PDF is an output format; use **Save project copy** for exact Markdown, forms, parts, layout, and metadata. Rich Markdown, DOCX, contents pages, nested parts, stanza widow controls, and annotated PDFs remain future work. Preview is limited to 500 pages and reports headings/glyphs that cannot fit. Windows PDF output is currently untagged.

Native Save confirmation governs replacement. WebView2 writes a temporary sibling; successful completion, a PDF signature check, and disk sync precede atomic replacement. Failure/cancellation preserves existing exports. One print runs at a time; preview navigation/close is held during printing. A 120-second timeout leaves the destination unchanged; late callbacks clean temporary output. Managed app-folder destinations are rejected. No arbitrary frontend path or broad filesystem permission is exposed.

## Implementation and verification

`domain/manuscript/` owns shared validated settings, ordering/counting, and deterministic pagination. `ManuscriptPage.vue` renders sheets, `PageSetup.vue` owns controls, and `ManuscriptView.vue` coordinates measurement/autosave/printing. Native `manuscript.rs` validates layout/metadata; `pdf.rs` owns the dialog-scoped print bridge and atomic finalization. Comments document persistence and print boundaries.

64 frontend tests and 32 native tests cover ordering, project counts, date/author output, invalid settings, Unicode wrapping, continuation, no source mutation, old formats, remapped section IDs, metadata/layout round trips, and preservation after PDF finalization failure. TypeScript/Vite, Clippy, and Windows builds pass. Real four-page Letter portrait and A4 landscape exports were rendered and visually checked, including a custom 1.25-inch left margin. Live Markdown remains byte-identical to earlier portable copies. Private writing is excluded from committed fixtures/artifacts.
